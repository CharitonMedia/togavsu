## Platform ceilings

1. `internal/supervisor/config.go` — firm settings come from environment values. Ceiling: no settings table. The core AC-030 walk skips `cmd/supervisor` and `internal/supervisor` because this is a separate process; a direct `ScanSource` call still reports a literal there. Upgrade: a SettingsReader backed by the core registry. Trigger: the settings registry is present in the database this process can read.
2. `internal/supervisor/ledger.go` — each schedule tick rereads the ledger. Ceiling: linear scan. Upgrade: keep a rebuilt tail offset beside the ledger. Trigger: a tick's scan exceeds 50ms or the file passes 50k events.
3. `internal/supervisor/mail.go` — admin notices append to an outbox file. Ceiling: no message leaves the host. Upgrade: core system mail drains the file. Trigger: SMTP settings or the email module can send.
4. `internal/supervisor/registry.go` — updates read one JSON release index. Ceiling: no OCI registry protocol. Upgrade: OCI tags plus cosign referrers. Trigger: phase 7 publishes a signed core image.
5. `internal/supervisor/destinations.go` — destination records live in a supervisor JSON file. Ceiling: not the core settings table. Upgrade: core backup-destination records push here. Trigger: `/api/v1/backup-destinations` is served by core.
6. `internal/supervisor/s3.go` — S3 copies use path-style SigV4 and buffer a put when the checksum is not already known. Ceiling: no virtual-hosted buckets and archive-sized buffers. Upgrade: virtual-hosted addressing and aws-chunked streaming. Trigger: a destination test returns PermanentRedirect or a backup copy exceeds 512 MiB.
7. `internal/supervisor/sftp.go` — SFTP shells out to OpenSSH. Ceiling: requires the `sftp` binary, a key, and `known_hosts`. Upgrade: an in-process client. Trigger: contracts permit `golang.org/x/crypto` or CI needs an in-process server.
8. `internal/supervisor/update.go` — automatic migration rollback returns `ErrPreserveWrites` and does not undo schema changes. Ceiling: later commits are kept and a failed migration's schema changes stay. Upgrade: a quiesced rollback that reverses only the migration. Trigger: a tested rollback preserves rows committed after the pre-update snapshot.
9. `Dockerfile` — the supervisor image runs as root for the Docker socket. Ceiling: one root container. Upgrade: a socket proxy limited to the engine calls this process makes. Trigger: phase 7 release hardening.
10. `compose.yaml` — the Caddy container runs as root so its entrypoint can read the upstream file and write certificates. Ceiling: root on the edge container. Upgrade: a non-root entrypoint image. Trigger: phase 7 release hardening.
11. `internal/supervisor/journal.go` — restore recovery rereads the journal. Ceiling: linear scan. Upgrade: keep the latest record per id beside the log. Trigger: a restart scan exceeds 50ms or the file passes 50k records.
12. `deploy/core/entrypoint.sh` — a 64-character hex field key is still exported as standard base64 of the same bytes. Ceiling: two on-disk encodings. Upgrade: reject hex. Trigger: bootstrap no longer finds a 64-character hex field_key.
13. `internal/supervisor/postgres.go` — `ApplyProductRestore` refuses an archive that lists file versions. Ceiling: database-only restore. Upgrade: a storage-backend adapter that writes each verified file and is covered by a restore test that reads the bytes back. Trigger: the files task registers that adapter with the supervisor.
14. `internal/supervisor/destinations.go`: `putFile` writes its receipt only after the temporary inode exists. Ceiling: a crash in that gap leaves at most one inode and two directory entries (the temp and, when linkat worked, its .own anchor) of 0 bytes or exactly the token prefix, and the later no-xattr clean file can add one more 0-byte name before its own journal, all with no receipt. Upgrade: journal an inode that is not yet linked. Trigger: the filesystem interface returns an inode before the directory entry exists.
15. `internal/supervisor/import.go`: a destination restore reads S3 and SFTP objects through their existing `Get`, which runs the whole transfer under the 2 minute destination I/O timeout, and SFTP lands the encrypted copy in the system temp directory before it is streamed to the backup volume. Ceiling: an archive that cannot transfer in 2 minutes fails with a destination error before writers stop. Path destinations time each read instead. Upgrade: a per-read idle deadline for S3 bodies and a progress-based SFTP timeout. Trigger: a destination restore or copy check of a real archive times out.

## Contracts ceilings

1. `internal/db/seed.go` — synthetic seed inserts one Missouri county. Ceiling: the counties table has a row. Upgrade path: first-run loads every county of the firm's state. Trigger: setup stores the firm state.
2. `internal/domain/defaults.go` — marketplace address default is the sentinel `togavsu-marketplace`, not a hostname. Ceiling: the setting exists and can be changed. Upgrade path: replace the sentinel with the marketplace origin. Trigger: the marketplace task publishes the service URL.
3. `internal/settings/check.go` — `fixedSite` skips integer literals, and duration selectors, inside enumerated functions (cents, UUID layout, synthetic seed builders, version bands, migration indexes, the ledger baseline, bootstrap key length and process status, sealing key width, setting upsert, the identity Argon2id, RFC 6238, password-minimum, AES-256, PHC, rate-window, and lock-wait functions, and practice algorithms: name scores, soundex, sort indexes, AES-256 key width, matter-number width, and page cursors). Practice reads firm limits from the registry, with the fallback numbers in `internal/domain/defaults.go`. Ceiling: a new configurable literal inside one of those functions is not reported. A different function in the same file is reported. The check is not AC-030 acceptance. Upgrade path: delete that function from `fixedSite`. Trigger: a configurable literal is added inside a listed function.
4. `internal/db/migrations/0001_core_schema.sql` — append-only tables are not immutable at the database. Interfaces omit update and delete, and there is no trigger because PRD section 6 forbids business-logic triggers. Ceiling: `TestAppendOnlyNotEnforcedAtDatabase` shows the application role can UPDATE and DELETE those rows. `InstallPrivileges` revokes UPDATE, DELETE and TRUNCATE on `audit_log` from PUBLIC and from the owning application role, and the non-owner writer has only SELECT and INSERT. The owner keeps grant options, so it can `GRANT` those privileges back to itself and then rewrite or delete rows, and it can `ALTER` or `DROP` the table. A superuser bypasses privileges; Compose now runs the core as the non-superuser `togavsu_app` (`deploy/postgres/core-role.sh`), and `scripts/ci/test-compose-first-run.sh` proves that role cannot UPDATE, DELETE or TRUNCATE `audit_log`. Upgrade path: move ownership of `audit_log` to a migration role so the application role is a non-owner with only SELECT and INSERT. Owners still open: identity `audit_log` (AC-018), practice `events` (AC-024), trust `trust_ledger` (AC-006), files `file_versions` and `file_renditions` (AC-039), modules `ai_call_log` (AC-031). Trigger: that task's acceptance claims the ledger cannot be edited or deleted.

## Identity ceilings

1. `internal/identity/service.go` — pending auth tokens expire after `security.lockout_length`. Ceiling: there is no challenge-lifetime setting. Upgrade path: add `security.challenge_ttl` to the registry and read it. Trigger: the registry defines `security.challenge_ttl`.
2. `internal/identity/service.go` — email lookup lists every user when the store has no `GetByEmail`. Ceiling: a full scan. Upgrade path: add `GetByEmail` to `repository.Users` and a unique email index. Trigger: a login's user scan exceeds 50ms.
3. `internal/identity/session.go` — API rate counts live in this process. Ceiling: a second core process has its own counter. Upgrade path: store the hits in Postgres. Trigger: more than one core process serves API traffic.
4. `internal/audit/service.go` and `internal/audit/postgres.go` — token id and module id are appended to the audit reason, and `CREATE ROLE` cannot run inside a goose transaction, so `InstallPrivileges` runs from bootstrap rather than as a migration. Ceiling: `audit_log` has no token or module columns. The table owner can `GRANT UPDATE, DELETE, TRUNCATE` back to itself after `InstallPrivileges` and then change rows, and can `ALTER` or `DROP` the table. A superuser bypasses privileges. Upgrade path: move ownership of `audit_log` to a migration role so the application role is a non-owner with only SELECT and INSERT, and add the columns in an identity migration. Trigger: the integration lead ships that migration and the app role is not the table owner and not a superuser.
5. `internal/identity/account.go` — first-run setup commits the admin, password, audit rows and TOTP enrollment in one transaction, but the three setup settings commit after it through the settings store's own transaction. Ceiling: a failed settings write leaves an inactive admin, which only the same email can resume. Upgrade path: the settings store joins `audit.WithTx`. Trigger: a setup with the same email cannot resume after a failed settings write.
6. `internal/audit/postgres.go` — `Rows` filters by entity, id, field, and time, and `audit_log_entity_idx` covers only entity and entity id. Ceiling: field and time are filtered across every audit row for that account. Upgrade path: the integration lead adds an index on (entity, entity_id, field, created_at). Trigger: one account's sign-in reads more than 10000 audit rows.
7. `internal/identity/pgstore.go` — lockout serialization uses `pg_try_advisory_lock(hashtextextended(user id))` and gives up after two seconds. Waiters release the pooled connection between tries. Ceiling: the winner still holds one connection while the callback uses others, so `SetMaxOpenConns(1)` can stall, and two different ids that hash together wait on each other. Upgrade path: run the failure check, the audit write, and the session insert on that lock connection. Trigger: a sign-in with `SetMaxOpenConns(1)` does not return.

## Practice ceilings

1. `internal/practice/durable.go` — the core's practice store keeps every practice row in the embedded `Memory`, loads all of `practice_records` (migration 200) at start, and runs each exported practice service mutation as one serialized unit (`Durable.Begin`): its records and `audit_log` rows commit in one transaction or, on any error, are discarded by reloading from Postgres. Ceiling: one core process per database, a full load at start, rows stored as JSON documents rather than in the section 5 relational tables (so rows seeded into `contacts` or `matters` do not appear on practice screens), and concurrent readers can see a unit's Memory changes before it commits, and until the reload if the commit fails. If that reload fails, the core exits rather than serve unstored rows, and Compose restarts it. Upgrade path: typed Postgres repositories over contacts, matters, matter_parties and notes with SQL filters, migrating `practice_records` into them. Trigger: a second core replica, a firm above 100k practice rows, a criterion that reads practice data from the relational tables, or a reader that must never see an uncommitted write.
2. `internal/practice/history.go` — audit and timeline updates return append-only from the service and the memory store. Ceiling: the application role can still UPDATE and DELETE `events` in Postgres. On `audit_log`, the owning application role can grant UPDATE, DELETE and TRUNCATE back to itself after `InstallPrivileges`. Upgrade path: reject those statements for the application role without a business-logic trigger, and move `audit_log` ownership to a migration role. Trigger: AC-024-F4 is run against Postgres as the application role.
3. `internal/practice/service.go` — `New` without a key seals SSN and EIN with a process-local AES-256-GCM key.
