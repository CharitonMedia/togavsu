# Simplification debt

Product acceptance is pending. Each entry names the file, the deliberate ceiling, the upgrade path, and the concrete upgrade trigger. The debt count is every numbered entry plus every standalone ponytail entry in this file; `python3 scripts/release/check_debt.py` checks it and that every marker in the repository names a trigger.

The first two entries are harness stand-ins. They are not product-ready behavior. `product_ready` stays false and their file hashes are refused as acceptance evidence.

2. `internal/supervisor/ledger.go` — each schedule tick rereads the ledger. Ceiling: linear scan. Upgrade: keep a rebuilt tail offset beside the ledger. Trigger: a tick's scan exceeds 50ms or the file passes 50k events.
3. `internal/supervisor/mail.go` — admin notices append to an outbox file. Ceiling: no message leaves the host. Upgrade: core system mail drains the file. Trigger: SMTP settings or the email module can send.
4. `internal/supervisor/registry.go` — updates read one JSON release index. Ceiling: no OCI registry protocol. Upgrade: OCI tags plus cosign referrers. Trigger: phase 7 publishes a signed core image.
5. `internal/supervisor/destinations.go` — destination records live in a supervisor JSON file that the core's `/api/v1/backup-destinations` fronts. Ceiling: not the core settings table, so a database restore leaves them as they are and the core lists them by reading this file. Upgrade: core backup-destination records push here. 7. `internal/supervisor/sftp.go` — SFTP shells out to OpenSSH. Ceiling: requires the `sftp` binary, a key, and `known_hosts`. Upgrade: an in-process client. Trigger: contracts permit `golang.org/x/crypto` or CI needs an in-process server.
8. `internal/supervisor/update.go` — automatic migration rollback returns `ErrPreserveWrites` and does not undo schema changes. 10. `compose.yaml` — the Caddy container runs as root so its entrypoint can read the upstream file and write certificates. Ceiling: root on the edge container. Upgrade: a non-root entrypoint image. Trigger: phase 7 release hardening.
11. `internal/supervisor/journal.go` — restore recovery rereads the journal. Ceiling: linear scan. Upgrade: keep the latest record per id beside the log. Trigger: a restart scan exceeds 50ms or the file passes 50k records.
12. `deploy/core/entrypoint.sh` — a 64-character hex field key is still exported as standard base64 of the same bytes. Ceiling: two on-disk encodings. Upgrade: reject hex. Trigger: bootstrap no longer finds a 64-character hex field_key.
13. `internal/supervisor/postgres.go` — `ApplyProductRestore` refuses an archive that lists file versions. Ceiling: database-only restore. Upgrade: a storage-backend adapter that writes each verified file and is covered by a restore test that reads the bytes back. Trigger: the files task registers that adapter with the supervisor.
14. `internal/supervisor/destinations.go`: `putFile` writes its receipt only after the temporary inode exists. Ceiling: a crash in that gap leaves at most one inode and two directory entries (the temp and, when linkat worked, its .own anchor) of 0 bytes or exactly the token prefix, and the later no-xattr clean file can add one more 0-byte name before its own journal, all with no receipt. 15. `internal/supervisor/import.go`: a destination restore reads S3 and SFTP objects through their existing `Get`, which runs the whole transfer under the 2 minute destination I/O timeout, and SFTP lands the encrypted copy in the system temp directory before it is streamed to the backup volume. Ceiling: an archive that cannot transfer in 2 minutes fails with a destination error before writers stop. Path destinations time each read instead. Upgrade: a per-read idle deadline for S3 bodies and a progress-based SFTP timeout. Trigger: a destination restore or copy check of a real archive times out.
16. `internal/core/backups.go` — `/api/v1/backups`, `/api/v1/backup-destinations` and `/api/v1/restores` return every row in one page (`next_cursor` null). Ceiling: the supervisor lists its whole backup volume, destination file and restore ledger on each call. Upgrade: cursor pages in the supervisor's list routes. 17. `docs/release/proposed-ci/release.yml` — the release workflow builds and pushes linux/amd64 images only. Ceiling: Docker Desktop on Apple Silicon runs them under emulation. 18. `internal/supervisor/operations.go` `rollBackFiles` — a restore's file set is checked and spooled before the database swap, but only the restarted core can write the bytes (it holds the storage backends' credentials and reads each object's location from the restored database), so the write runs after writers restart. The restarted core starts held: it serves only its health check and the supervisor's file import, and starts no background worker, until the supervisor's `GET /v1/restores/hold` says no restore's file bytes are pending and no file rollback is running (`internal/core/restorehold.go`, `Operations.FileHold`). Ceiling: a rollback that also fails lifts the hold and leaves the restored database live over the files it could not write (`files_not_restored`, admin mailed), and a supervisor that never answers keeps the core closed to users. Upgrade path: keep the replaced database until the import succeeds, so a failed write needs no second restore. Trigger: a firm reports a `files_not_restored` restore, or a held core that stayed closed.

## Contracts ceilings

1. `internal/db/seed.go` — synthetic seed inserts one Missouri county. Ceiling: the counties table has a row. Upgrade path: first-run loads every county of the firm's state. Trigger: setup stores the firm state.
2. `internal/domain/defaults.go` — marketplace address default is the sentinel `togavsu-marketplace`, not a hostname. Ceiling: the setting exists and can be changed. Upgrade path: replace the sentinel with the marketplace origin. Trigger: the marketplace task publishes the service URL.
3. `internal/settings/check.go` — `fixedSite` skips integer literals, and duration selectors, inside enumerated functions (cents, UUID layout, synthetic seed builders, version bands, migration indexes, the ledger baseline, bootstrap key length and process status, sealing key width, setting upsert, the identity Argon2id, RFC 6238, password-minimum, AES-256, PHC, rate-window, and lock-wait functions, and practice algorithms: name scores, soundex, sort indexes, AES-256 key width, matter-number width, and page cursors). Practice reads firm limits from the registry, with the fallback numbers in `internal/domain/defaults.go`. Ceiling: a new configurable literal inside one of those functions is not reported. A different function in the same file is reported. The check is not AC-030 acceptance. Upgrade path: delete that function from `fixedSite`. Trigger: a configurable literal is added inside a listed function.
4. `internal/db/ledgers.go` — append-only tables are immutable at the database by ownership, not by trigger (PRD section 6). `core migrate` (Compose service `migrate`, `core.MigrateSealed`) applies the migrations on a superuser session switched to `togavsu_app` (`db.ApplySealed`). A migration whose SQL names an append-only table gets those tables handed to `togavsu_app` at the start of its own transaction and sealed again before it commits, so no other session, including the old core serving during an update, ever sees a ledger it could change, and a failed, cancelled or killed migration rolls the handoff back (`TestLedgersSealedForApplicationRole` kills the migrating backend mid-migration; `TestWrapLedgerMigration`). Migrations that name no ledger run with no handoff. `core migrate` then seals again as the Postgres superuser, handing schema `core` and `audit_log`, `trust_ledger`, `events`, `ai_call_log`, `file_versions` and `file_renditions` to the NOLOGIN `togavsu_ledger_owner`; `togavsu_app` keeps SELECT, INSERT and REFERENCES (id) and is not a member of the owner, so UPDATE, DELETE, TRUNCATE, ALTER, DROP and GRANT-back fail (`TestLedgersSealedForApplicationRole`, `scripts/ci/test-compose-first-run.sh`). The superuser URL is only in the `adminsecrets` volume, which only `migrate` and the supervisor mount; the serving core mounts `appsecrets` read-only, its entrypoint refuses to serve when it can see the superuser URL, `core migrate` fails without it and checks the seal afterwards (`db.VerifySealed`), the serving core refuses an unsealed database (`core.Config.RequireSealed`), and a supervisor restore runs the same `ledgerseal.Script` on the loaded copy before the swap (`TestRestoreSealsLedgers`). Ceiling: a superuser, and so the supervisor process, still bypasses privileges; and a core opened in-process without `RequireSealed` (Go tests, a hand-run binary) owns the tables as before. Upgrade path: a supervisor that holds a narrower role than the Postgres superuser for restore and measurement. Trigger: a supervisor compromise review, or a restore that needs no superuser. Second ceiling: a migration that names a ledger holds an ACCESS EXCLUSIVE lock on the tables it names until it commits, so the serving core's writes to them wait for that one migration; tables are matched by name in the SQL text, so a migration that alters a ledger only through dynamic SQL fails closed on permissions instead of applying. Upgrade path: split long ledger data migrations into batches outside the ownership transaction. Trigger: a ledger migration that stalls core writes in the update load test, or one that needs dynamic DDL on a ledger.
